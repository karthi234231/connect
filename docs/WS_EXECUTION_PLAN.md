## 0. Application flow — page to page (verified against `proxy.ts` + routes)

The proxy (`proxy.ts`) gates: `/dashboard/:path*`, `/api/:path*`, `/login`,
`/callback`, `/admin/:path*`, `/traction`, `/settings/security`.

```
GUEST (unauthenticated)
  / ............................. app/page.tsx  (marketing demo home)
  ├─ /login .................... static form TODAY; WS-1 wires real auth action + turnstile
  │      └─ on auth success ──► proxy redirects → /dashboard
  ├─ (marketing)/browse ........ public ideas+events guest gateway (/api/browse)
  ├─ /events/search ............ public event search (real, wired)  ── WS-2 hardens
  ├─ /events/[eventId] ......... PUBLIC event detail — TODAY MOCK CATALOG; WS-2 rewires to /api/browse + RSVP/waitlist/ics
  └─ /privacy · /terms ......... legal

AUTHENTICATED (proxy injects x-user-id/x-request-id)
  /dashboard ................... hub: matches/messages/events stats (real fetches) ── WS-4/5 verify
  ├─ /dashboard/onboarding ..... static step list  ── WS-5 wires real profile tiers + completeness
  ├─ /dashboard/chat .......... thread list (real) → /dashboard/chat/[matchId] (thread-view, real) ── WS-5 hardens composer/states
  ├─ /dashboard/matches ....... match cards (real) ── WS-5 adds reasons chips + actions
  ├─ /dashboard/connections ... connections + requests (real) ── WS-4 accepts/rejects + momentum
  ├─ /dashboard/ideas ......... list/new/[ideaId]/edit ── WS-4 join-request + collaborator review
  ├─ /dashboard/events ........ organizer pages (new/edit/[eventId]/attendees/analytics) ── WS-2 analytics export + guest RSVP link into dashboard
  ├─ /dashboard/notifications . real inbox ── checked (wired)
  ├─ /dashboard/profile ....... view/preview/edit ── WS-4 wires real save + completeness meter
  └─ /dashboard/settings ....... 404 TODAY (no index page) ── WS-4 creates index + wires 6 sub-pages
        └─ /settings/security .. WS-1 MFA surfacing
  /admin ....................... card grid linking to /dashboard ── WS-3 builds real sub-pages (moderation/users/events/audit)
  /api/* ....................... browse/search/health public; rest authed (withAuth) ── WS-3 adds Turnstile-verified auth surface if needed
  /suspended ................... guarded notice (exists)
```

**Key flow decisions this plan encodes:**
- `/` stays the demo marketing home (no route-group move this pass — STR-09 is
  deferred; moving `app/page.tsx` risks the visual snapshot). Only WS-5 may add
  real data calls into the existing dashboard hub; the home demo itself is out
  of scope to avoid restyle risk. The **dashboard hub** is the functional home.
- `/dashboard/settings` **must become 200** (STR-10) — it is a nav dead-end today.
- `/events/[eventId]` **must become live** (UI-10): RSVP seat counter, waitlist
  join + promoted banner, `.ics` export via `lib/calendar.ts`, share links —
  all inside the EXISTING event card layout, no reskin.
- `/admin` **must become a real console** (UI-22) with the existing card grid
  but each card navigating to a real data page (moderation queue, users +
  suspend, event audit, audit-log viewer).
- Path wiring driven entirely by `config/routes.ts` (`ROUTES.*`) — no
  hard-coded hrefs in new work (import `ROUTES`).

Use `useActionState`/`useTransition` as the codebase does elsewhere. Show errors
